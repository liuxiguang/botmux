# 企业微信员工账号通道

用户目标：在现有企微版本上，用授权员工账号收发消息并交给 Codex；优先官方事件推送。

## 已验证边界

- 2026-09-21：当前账号使用 `wecom-cli message send` 向专用测试群发送文本，随后查询消息记录，发送者与 `identity whoami` 的授权员工一致。CLI 通用身份说明不足以判定这个具体方法的实际发送身份；该实测不代表其他企业/授权同样可用。
- 智能机器人 WebSocket 只订阅机器人消息，不能作为员工私聊入口。
- 官方会话存档 `msgaudit_notify` 是加密 HTTP 回调，通知后需要拉取正文；官方文档写明 15 秒通知间隔。它不是逐消息 WebSocket。
- 当前 CLI 可读群正文，单聊参数已公开但当前账号私聊读取仍需验证。QPS 未公示；查询返回没有稳定消息 ID。

## 实现

在 `wecom serve` 配置中添加显式 employee 模式，默认 bot 模式保持不变。复用现有 core-only、SQLite 任务队列、串行会话和出站结果状态。新模块负责员工配置、CLI 调用、增量消息采集、回调认证与生命周期。

员工身份必须与配置一致，发送前重新校验。只采集明确配置的会话，并继续检查成员/群白名单。默认忽略员工自己发送的消息；只有显式 `/codex ` 前缀可作为本机自测入口。群默认也要求此前缀，私聊允许成员直接提问。不同联系人隔离上下文，同群共享。

轮询首启从当前时间开始，不执行历史聊天。按会话持久化时间水位，重叠查询并全页读取后再按时间入队；根据会话、发送者、秒级时间、内容和同秒重复次数生成稳定指纹。没有平台消息 ID，因此不能承诺端到端 exactly-once；停机超过 7 天必须报告历史缺口。忽略自己的回复，避免循环。未知发送结果保持 unknown，不自动重发。

回调只接受签名正确、AES 解密成功、企业身份匹配的官方 msgaudit_notify。支持 GET URL 验证、POST 通知、时效/重放校验、请求体限制。回调只唤醒授权 CLI 采集，不把任意 HTTP 正文当作用户指令。默认监听 loopback，公网 HTTPS 由操作者配置反代；没有官方配置时明确报告仅轮询。

## 验证与部署

覆盖身份错误、自己消息过滤、前缀、分页乱序、重复文本、重启水位、限流退避、错误发送不重试、真实 HTTP 加密回调及长回复分段。运行既有企微和 core-only 回归、完整构建；部署独立员工测试实例，只允许测试群。真实回调验收依赖管理员开通并提供本机私有配置；不得把本地协议测试说成平台实测。

## 影响面

共享变更限于企微配置、bridge 的规范化消息入口/发送长度、store 水位和 runtime 选择。保持飞书 owner、CLI adapter、PTY/tmux 逻辑不变。命令子进程不经 shell，代码兼容 macOS/Linux；本机实测为 macOS，Linux 不宣称已实测。

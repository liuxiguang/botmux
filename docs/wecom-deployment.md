# botmux 企业微信部署指南

目标：让你自己的企业微信机器人，调用你电脑上的 Codex 执行任务并回复结果。你负责账号、授权和测试消息，Agent 负责本地部署。

## 人需要做什么

1. **准备一台能持续运行的电脑或服务器**，让 Agent 可以使用它的终端。首次建议用 macOS；Linux / WSL2 需在自己的机器上实测。
2. **申请自己的机器人**：企业微信「工作台 → 智能机器人 → 创建 → 手动创建 → API 模式 → 使用长连接」。没有入口时请企业管理员协助。保存 Bot ID 和 Secret，设置可使用成员；需要群聊时把机器人加入内部测试群。
3. **完成模型登录**：让 Agent 安装或检查 Codex，按提示在浏览器完成你自己的账号授权。
4. **告诉 Agent 三件事**：机器人要操作哪个项目目录、允许哪些成员使用、是否需要在哪个群里使用。根据 Agent 提示，把机器人 Secret 填到本机私有文件，不必发到聊天里。
5. **配合发送测试消息**：先单聊，成功后再测试群聊。确认最终答案确实出现在你的企微客户端。

## Agent 需要做什么

| 顺序 | 操作 | 完成标志 |
| --- | --- | --- |
| 1 | 检查系统、网络及 Git、Bun 1.4.2、Node ≥ 22.13、tmux、Python 和 Codex；补齐缺少的依赖 | 工具可运行，Codex 实际计算一次成功 |
| 2 | 独立克隆下方仓库的 `codex/wecom-support` 分支，安装依赖并构建 | 构建通过，记录实际 commit |
| 3 | 建立本实例的私有配置、状态目录和工作目录，取得本人/测试群的认证标识，按本人确认的范围配置白名单 | 使用自己的机器人、独立目录及空闲端口 |
| 4 | 校验配置，使用 `wecom serve` 启动；先跑通本人单聊，再开放需要的群 | 本次日志出现 authenticated 和 ready |
| 5 | 对照企微回复检查本地任务完成和最终结果投递，配置后台运行 | 客户端收到正确结果；后台启动后重测也通过 |
| 6 | 交付实际启动、停止、重启、日志命令，以及本机路径和测试结果 | 本人以后能独立管理；未测内容明确标注 |

代码：[liuxiguang/botmux · codex/wecom-support](https://github.com/liuxiguang/botmux/tree/codex/wecom-support)。本次功能在该分支，不能用 master 或 npm 正式版代替。

具体安装命令、配置格式和启停脚本由 Agent 按 [GitHub 详细执行手册](https://github.com/liuxiguang/botmux/blob/codex/wecom-support/docs/wecom-deployment-runbook.md)操作；人不需要逐段执行长脚本。自己手工部署时也可使用这份手册。

## 可以直接发给 Agent

```text
请在我这台机器上部署 botmux 企业微信版。
读取 https://github.com/liuxiguang/botmux/blob/codex/wecom-support/docs/wecom-deployment-runbook.md ，按实际环境执行。
使用我自己的机器人和 Codex 登录，独立目录、状态文件和端口。
需要我创建机器人、扫码登录、在本机填写 Secret 或发测试消息时再找我配合。
先验收单聊，再按我确认的范围启用群聊，最后配置后台运行。
完成后给我启动、停止、重启和日志命令，并分别列出已验证与未验证的项目。
```

## 怎么算部署成功

- 单聊发送“计算 17×19，只返回结果”，收到最终答案 **323**；只有“已接收任务”还不算成功。
- 再发送一个测试词并追问，能继续同一段对话；需要群聊时，在群内 @机器人重复测试。
- Agent 能在本地日志中对应到这次任务完成及最终回复投递成功；转后台后再次测试通过。

同一机器人只运行一个接入服务。授权成员共享该机器人在本机的操作能力，同群成员共享会话；只开放给可信成员。机器需保持运行和联网，后台运行是否能在重启后恢复，应由 Agent 单独说明。

原理与适配说明见 [botmux 运行原理与企业微信适配](wecom-onboarding.md)。
